HISTORIQUE DU PROJET - TOUTES LES ETAPES + COMMANDES
======================================================
Repo : https://github.com/AlphaSix-Development/LauncherMinecraft.git
API prod : http://89.168.51.174:3001 (port 3001) | BDD : MySQL "Launcher" (meme serveur)

------------------------------------------------------
ETAPE 1 - BASE : launcher Electron + API auth + Docker
------------------------------------------------------
Fait : app Electron (connexion / inscription / ecran connecte),
API Express + MySQL + JWT + bcrypt, docker-compose (api + MySQL docker).
Fichiers : launcher/, server/src/*, docker-compose.yml, README.md, INSTALL_LINUX.txt.

Deployer (Linux) :
  git clone https://github.com/AlphaSix-Development/LauncherMinecraft.git
  cd LauncherMinecraft
  cp .env.example .env && nano .env
  docker compose up -d --build
  curl http://localhost:3001/api/health

Exe (PC Windows) :
  cd launcher && npm install && npm run dist
  # -> dist/MonLauncher Setup 0.1.0.exe

------------------------------------------------------
ETAPE 2 - API BRANCHEE SUR TON MYSQL (phpMyAdmin)
------------------------------------------------------
Fait : l'API ecrit dans TA base "Launcher" au lieu du MySQL Docker
(DB_HOST=host.docker.internal, MySQL Docker en option --profile mysql-docker).
Fichiers : docker-compose.yml, .env.example, server/schema-externe.sql.

Commandes (Linux) :
  # creer table + user dans phpMyAdmin (onglet SQL), puis :
  grep -r bind-address /etc/mysql/   # si 127.0.0.1 -> mettre 0.0.0.0 + restart mysql
  sudo ufw allow from 172.16.0.0/12 to any port 3306
  sudo ufw allow 3001/tcp

ETAPE 3 - DIAGNOSTIC 409 + PORT 3001 PARTOUT
------------------------------------------------------
Fait : tout passe en 3001 (compose, API, launcher, docs).
Le 409 "deja utilise" = compte existant -> utiliser /login.
Test inscription / connexion :
  curl -X POST http://localhost:3001/api/auth/register -H "Content-Type: application/json" -d '{"username":"Test_01","email":"test@mail.com","password":"secret123"}'
  curl -X POST http://localhost:3001/api/auth/login -H "Content-Type: application/json" -d '{"identifier":"Test_01","password":"secret123"}'

ETAPE 4 - TAG ADMIN (owner BDD uniquement)
------------------------------------------------------
Fait : colonne users.role (migration auto au boot), role dans JWT + /me,
middleware requireAdmin (relit la BDD a chaque appel), badge/admin auto.
Aucune route n'accepte role en entree.
SQL (phpMyAdmin, base Launcher) :
  ALTER TABLE users ADD COLUMN role ENUM('user','admin') NOT NULL DEFAULT 'user';
  UPDATE users SET role = 'admin' WHERE username = 'AlphaSix';
  SELECT id, username, email, role FROM users;

ETAPE 7 - MODS : UPLOAD / SERVING / SYNC (P2, fait)
------------------------------------------------------
Fait : upload drag-drop (zip extrait + jar seuls, champ "mods", max 5 fichiers,
MAX_MOD_MB=512), validation (extension + signature zip), stockage par sha1
(dedup multi-serveurs) dans volume mods_data:/app/files, manifeste
GET /api/servers/:id/mods (sha1 + url pour synchro launcher),
telechargement GET /api/files/:sha1 (cache immutable),
suppression mod + nettoyage orphelins, bump modpack_version auto,
suppression serveur = fichiers orphelins nettoyes.
Fichiers : server/src/files.js (nouveau), routes/files.js (nouveau),
routes/admin.js, routes/servers.js, docker-compose.yml, README.md.

Tester (apres git pull + rebuild Linux, TOKEN = compte tag admin) :
  # upload (remplace UNZIP.zip par un vrai zip/jar) :
  curl -X POST http://localhost:3001/api/admin/servers/1/mods -H "Authorization: Bearer TOKEN" -F "mods=@mods.zip"
  # attendu : {"modpack_version":2,"added":[...],"skipped":0}
  curl http://localhost:3001/api/servers/1/mods
  curl -o mod.jar http://localhost:3001/api/files/SHA1_ICI
  curl -X DELETE http://localhost:3001/api/admin/mods/1 -H "Authorization: Bearer TOKEN"

ETAPE 8 - P3+P4 : SERVEURS DANS LE LAUNCHER + JEU CRACK (fait)
------------------------------------------------------
P3 admin (tag requis) : sous-menu Serveurs (liste + creer/editer/supprimer),
versions MC (liste Mojang) + Forge (maven), drag-drop zip/jar avec progression,
liste mods + suppression, n° modpack affiche.
P4 joueur : bouton Jouer (menu gauche) -> cartes serveurs -> JOUER.
Lancement : Java detecte (8/17/21 selon MC), mods synchronises (sha1),
servers.dat avec serveur en premier, MCLC offline (pseudo + UUID offline).
Une seule instance : autre serveur -> popup "En attente de la fermeture
du jeu" + bouton Fermer -> auto-lancement. Progression + logs.
Fichiers : launcher/game/*.js (nouveau), main.js, preload.js, renderer/*,
package.json (dep minecraft-launcher-core).
Exe rebuild : cd launcher && npm run dist.
VOIR : SERVERS.txt (tuto complet).
