TUTO COMPLET - API LAUNCHER MINECRAFT SUR LINUX (Ubuntu / Debian)
API Express + TON MySQL (visible dans phpMyAdmin) - Port API : 3001
====================================================================================
Repo : https://github.com/AlphaSix-Development/LauncherMinecraft.git

0. SUPPRIMER L'ANCIEN TUTO (si tu as deja clone le repo avant)
--------------------------------------------------------------
Les anciens fichiers MYSQL_EXTERNE.txt et DEPANNAGE_409.txt n'existent plus,
tout est fusionne ICI. Sur ton Linux, apres le git pull, nettoie :
  cd ~/LauncherMinecraft
  git pull
  rm -f MYSQL_EXTERNE.txt DEPANNAGE_409.txt
  ls *.txt
  # Tu ne dois voir que : INSTALL_LINUX.txt

1. PREREQUIS
------------
  docker --version
  docker compose version

Si manquant :
  sudo apt update && sudo apt install -y docker.io docker-compose-plugin
  sudo systemctl enable --now docker
  sudo usermod -aG docker $USER  (puis reconnecte-toi)

Il faut aussi : MySQL installe sur le serveur + acces phpMyAdmin.

2. RECUPERER LE PROJET
----------------------
Premier clone :
  git clone https://github.com/AlphaSix-Development/LauncherMinecraft.git
  cd LauncherMinecraft

Mises a jour suivantes :
  git pull
  docker compose up -d --build

3. PREPARER TON MYSQL (via phpMyAdmin)
--------------------------------------
a) Table users : clique sur ta base (ex : Launcher) -> onglet SQL ->
   colle le contenu de server/schema-externe.sql -> Executer.
   Verifie : la table users apparait dans la base.

b) User dedie a l'API (onglet SQL, sans selectionner de base).
   Remplace MOT_DE_PASSE_FORT et Launcher si ta base a un autre nom :
     CREATE USER IF NOT EXISTS 'launcher_api'@'%' IDENTIFIED BY 'MOT_DE_PASSE_FORT';
     GRANT ALL PRIVILEGES ON Launcher.* TO 'launcher_api'@'%';
     FLUSH PRIVILEGES;

c) Autoriser Docker a joindre MySQL (en SSH sur le Linux).
   Le conteneur ne peut PAS utiliser "localhost", il passe par
   host.docker.internal (= l'hote). MySQL doit donc l'accepter :
     sudo ss -tlnp | grep 3306
     grep -r bind-address /etc/mysql/ 2>/dev/null
   Si bind-address = 127.0.0.1, Docker sera REFUSE. Corrige :
     sudo nano /etc/mysql/mysql.conf.d/mysqld.cnf
     # mets : bind-address = 0.0.0.0
     sudo systemctl restart mysql
   Si ufw actif, autorise le reseau Docker vers MySQL :
     sudo ufw allow from 172.16.0.0/12 to any port 3306

4. CONFIGURER LE .ENV (a la racine du projet)
---------------------------------------------
  cp .env.example .env
  nano .env

  DB_HOST=host.docker.internal  (ne pas changer : c'est l'hote vu depuis Docker)
  DB_PORT=3306
  DB_USER=launcher_api
  DB_PASSWORD=MOT_DE_PASSE_FORT   (celui de l'etape 3.b)
  DB_NAME=Launcher                (nom EXACT de ta base phpMyAdmin, casse respectee)
  JWT_SECRET=<colle ici le resultat de : openssl rand -base64 48>

5. LANCER L'API
---------------
  docker compose up -d --build
  docker compose ps
  docker compose logs -f api
  # Attends ces lignes :
  #   [DB] MySQL connecte + table users OK
  #   [API] http://localhost:3001 -> /api/health
  # CTRL+C pour quitter les logs (ca continue en fond).

6. VERIFIER (sur le Linux)
--------------------------
  curl http://localhost:3001/api/health
  # attendu : {"ok":true,"time":"..."}

  # Inscription (1ere fois seulement) :
  curl -X POST http://localhost:3001/api/auth/register \
    -H "Content-Type: application/json" \
    -d '{"username":"Test_01","email":"test@mail.com","password":"secret123"}'
  # attendu : {"token":"...","user":{...}}
  # Puis dans phpMyAdmin : base Launcher -> users -> Parcourir : tu dois voir Test_01.

  # Connexion (compte existant) :
  curl -X POST http://localhost:3001/api/auth/login \
    -H "Content-Type: application/json" \
    -d '{"identifier":"Test_01","password":"secret123"}'
  # attendu : {"token":"...","user":{...}}

  # Verifier un token :
  TOKEN=colle_ton_token_ici
  curl http://localhost:3001/api/auth/me -H "Authorization: Bearer $TOKEN"
  # attendu : {"user":{...}}

7. ERREUR 409 "Pseudo ou email deja utilise" : C'EST NORMAL
----------------------------------------------------------
Le 409 n'est PAS un bug. L'API repond 409 quand le pseudo ou l'email
existe DEJA dans users. Ca veut dire que ton tout premier appel register
avait reussi. Ne rejoue pas register : utilise /login (etape 6).
Et cherche les donnees dans la base utilisee par l'API (DB_NAME du .env,
ex : Launcher), table users :
  docker compose exec db 2>/dev/null; docker exec $(docker ps -q) true 2>/dev/null
  # Le plus simple : regarde directement dans phpMyAdmin -> base -> users -> Parcourir.
Si 409 des le TOUT premier essai : le volume db_data ou ta base contient
deja des donnees d'un run precedent. Pour repartir de zero (MySQL Docker) :
  docker compose --profile mysql-docker down -v
  (Pour ton MySQL : supprime la ligne dans phpMyAdmin -> users -> Supprimer.)

8. OUVRIR LE PORT POUR LE LAUNCHER
----------------------------------
  ss -tlnp | grep 3001
  sudo ufw allow 3001/tcp
  sudo ufw status

  Depuis ton PC Windows :
  curl http://IP_SERVEUR:3001/api/health
  # ex : http://51.91.12.34:3001/api/health
  Si firewall cloud (OVH/Hetzner...) : ouvre aussi le port 3001 dans le panel.

9. POINTER LE LAUNCHER VERS LE SERVEUR
--------------------------------------
Sur ton PC, edite launcher/config.json :
  {
    "apiUrl": "http://IP_SERVEUR:3001",
    "serverName": "Mon Serveur"
  }

  cd launcher
  npm install
  npm start       (test dev)
  npm run dist    (genere dist/MonLauncher-Setup-*.exe)

10. SECOURS : UTILISER LE MYSQL DOCKER (au lieu du tien)
--------------------------------------------------------
  nano .env   # mets DB_HOST=db  et  DB_NAME=launcher_minecraft
  docker compose --profile mysql-docker up -d --build

11. MAINTENANCE
---------------
  docker compose logs -f            # logs live
  docker compose logs -f api        # API seule
  docker compose up -d --build      # rebuild apres git pull
  docker compose down               # stop
  docker volume ls                  # db_data = persistance MySQL Docker (secours)

12. DEPANNAGE RAPIDE
--------------------
- API boucle "[DB] tentative ... retry" : .env faux ou MySQL injoignable.
  Verifie DB_HOST/DB_USER/DB_PASSWORD/DB_NAME + etape 3.c.
- "Access denied for user 'launcher_api'" : mauvais password ou user cree
  sans '%' -> refais l'etape 3.b, verifie dans phpMyAdmin -> Comptes utilisateurs.
- "Unknown database 'Launcher'" : faute de frappe dans DB_NAME.
- "Table 'Launcher.users' doesn't exist" : etape 3.a non faite.
- curl OK en local mais pas depuis PC : ufw / firewall cloud / mauvaise IP.
  Teste : telnet IP_SERVEUR 3001.
- Port 3001 deja pris : change le mapping dans docker-compose.yml
  (ex "3002:3001") + apiUrl http://IP:3002 + ufw allow 3002/tcp.

FIN - Si /api/health repond sur le port 3001 ET que phpMyAdmin montre
les users dans ta base, tout est OK : ton launcher peut se connecter.
