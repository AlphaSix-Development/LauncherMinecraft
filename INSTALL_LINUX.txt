INSTALLATION API + BDD SUR LINUX (Ubuntu / Debian)
Launcher Minecraft - API Express + MySQL (meme serveur via Docker)
====================================================================

1. PREREQUIS SUR TON LINUX
--------------------------
Docker + Compose deja installes. Verifie :
  docker --version
  docker compose version

Si manquant :
  sudo apt update && sudo apt install -y docker.io docker-compose-plugin
  sudo systemctl enable --now docker
  sudo usermod -aG docker $USER  (puis reconnecte-toi)

2. TRANSFERER LE PROJET SUR LE LINUX
------------------------------------
Depuis ton PC Windows (PowerShell) :
  scp -r E:\LauncherMinecraft user@IP_SERVEUR:/home/user/LauncherMinecraft

Puis sur le Linux :
  cd ~/LauncherMinecraft
  ls -R | head -30
  # tu dois voir : docker-compose.yml, .env.example, server/, launcher/

3. CONFIGURER LE .ENV PROD (a la racine)
----------------------------------------
  cp .env.example .env
  nano .env

Contenu a mettre (exemple) :
  DB_PASSWORD=TonMotDePasseFort123!_change_moi
  DB_NAME=launcher_minecraft
  JWT_SECRET=colle_ici_48_caracteres_aleatoires

Generer un JWT_SECRET fort :
  openssl rand -base64 48

IMPORTANT :
- C'est le .env RACINE qui compte (lu par docker-compose.yml).
- Ne touche pas a DB_HOST=db (c'est le nom interne Docker, api -> db).
- Ne mets pas d'espaces autour du =.

4. LANCER API + BDD
-------------------
  docker compose up -d --build
  docker compose ps
  docker compose logs -f api
  # Attends ces lignes :
  #   [DB] MySQL connecte + table users OK
  #   [API] http://localhost:3000 -> /api/health
  # CTRL+C pour quitter les logs (ca continue en fond).

5. VERIFIER QUE CA REPOND (sur le Linux)
----------------------------------------
  curl http://localhost:3000/api/health
  # attendu : {"ok":true,"time":"..."}

  # Test inscription :
  curl -X POST http://localhost:3000/api/auth/register \
    -H "Content-Type: application/json" \
    -d '{"username":"Test_01","email":"test@mail.com","password":"secret123"}'
  # attendu : {"token":"...","user":{...}}

  # Test connexion :
  curl -X POST http://localhost:3000/api/auth/login \
    -H "Content-Type: application/json" \
    -d '{"identifier":"Test_01","password":"secret123"}'

  # Test token :
  TOKEN=colle_ton_token_ici
  curl http://localhost:3000/api/auth/me -H "Authorization: Bearer $TOKEN"

6. OUVRIR LE PORT POUR LE LAUNCHER
----------------------------------
  ss -tlnp | grep 3000
  sudo ufw allow 3000/tcp
  sudo ufw status

  Depuis ton PC Windows (PowerShell ou navigateur) :
  curl http://IP_SERVEUR:3000/api/health
  # remplace IP_SERVEUR par l'IP publique du VPS, ex : http://51.91.12.34:3000/api/health

  Si OVH / Hetzner / firewall cloud : ouvre aussi le port 3000 dans le panel.

7. POINTER LE LAUNCHER VERS LE SERVEUR
--------------------------------------
Sur ton PC, edite launcher/config.json :
  {
    "apiUrl": "http://IP_SERVEUR:3000",
    "serverName": "Mon Serveur"
  }

Puis rebuild l'exe :
  cd launcher
  npm install
  npm start       (test dev)
  npm run dist    (genere dist/MonLauncher-Setup-0.1.0.exe)

8. MAINTENANCE
--------------
  docker compose logs -f            # voir logs live
  docker compose logs -f api        # logs API seule
  docker compose logs -f db         # logs MySQL
  docker compose down               # stop
  docker compose up -d              # restart
  docker compose up -d --build      # rebuild apres modif server/
  docker volume ls                  # db_data = donnees MySQL persistantes

  Mettre a jour apres modif du code :
  Sur Linux : git pull OU re-scp, puis docker compose up -d --build

9. DEPANNAGE
------------
- API boucle "[DB] tentative ... retry" :
  -> .env faux / db pas healthy. Verifie : docker compose logs db, docker compose ps
- "JWT_SECRET trop court" dans les logs :
  -> regenere un secret 48 chars dans .env puis up -d
- curl OK en local mais pas depuis PC :
  -> firewall ufw / firewall cloud / mauvaise IP. Teste : telnet IP 3000
- "Pseudo ou email deja utilise" (409) : normal, compte deja cree. Teste login.
- Port 3000 deja pris :
  -> change dans docker-compose.yml "3001:3000" puis apiUrl http://IP:3001
- Reset complet BDD (ATTENTION efface tout) :
  docker compose down -v
  docker compose up -d --build

10. SECURITE (mode IP:port = test, pas prod publique longue duree)
------------------------------------------------------------------
- DB_PASSWORD fort + JWT_SECRET 48 chars minimum.
- Le port 3306 MySQL ne doit JAMAIS etre expose (reste interne, c'est deja le cas).
- Pour du public durable : passe en domaine + HTTPS (Nginx/Caddy reverse proxy).
- Sauvegarde : docker exec ... mysqldump ou snapshot volume db_data.

FIN - Si /api/health repond depuis ton PC, ton launcher peut se connecter.
