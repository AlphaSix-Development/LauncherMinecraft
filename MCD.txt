MCD - LAUNCHER MINECRAFT (BDD MySQL)
===================================
Base : celle du .env (DB_NAME, ex : Launcher). Gerable via phpMyAdmin.

ENTITE UNIQUE (pas d'association)
---------------------------------
  JOUEUR  (table users)
  - id            : INT, PK, auto
  - username      : VARCHAR(16), UNIQUE
  - email         : VARCHAR(255), UNIQUE
  - password_hash : VARCHAR(255, bcrypt, jamais en clair)
  - role          : ENUM('user','admin'), defaut 'user'  <- TAG ADMIN
  - created_at    : TIMESTAMP

MLD (Modele Logique)
--------------------
  users (id#, username*, email*, password_hash, role, created_at)
  (# = cle primaire, * = UNIQUE ; pas de cle etrangere)

TAG ADMIN (seul le owner BDD le donne, en SQL direct)
-----------------------------------------------------
  Donner :  UPDATE users SET role = 'admin' WHERE username = 'TonPseudo';
  Retirer : UPDATE users SET role = 'user'  WHERE username = 'TonPseudo';
  Aucune route API n'accepte role en entree (ni register, ni login).
  Effet : le launcher affiche la section admin auto (sans 2e login),
  et /api/admin/* exige le tag relu en BDD a chaque appel.
  Revoque = acces coupe en ~30s max, sans deconnexion a gerer.
